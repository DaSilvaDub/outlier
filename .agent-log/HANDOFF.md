- **PR #109 summary**: Implements the "Tier 1 — Restore truth" ledger upgrade plan. (1) Recovery: `feedback recover --corrupted <path> --output <path>` salvages a corrupted `feedback.sqlite3` into a fresh, schema-current database (sqlite3 CLI `.recover` piped straight into a second `sqlite3` process when installed, a row-by-row direct-salvage fallback otherwise). Copy any `-wal`/`-shm` companions alongside the corrupted file under the same stem first, or not-yet-checkpointed rows in them are unrecoverable. (2) CLV fix: root-caused `clv_line == 0.0000` across historical rows — `_latest_local_close` was picking the *taken* snapshot as its own "close" whenever an outcome had only ever been captured once, silently reporting a false, precise zero instead of "unknown". Fixed to require a genuinely distinct **and later** local capture (`find_distinct_closing_snapshot` now takes a required `after_captured_at` bound — excluding the taken snapshot's own id was not enough on its own, since an older-only history was still getting returned as a fabricated "close"), falling back to the current `*_line_movement_latest.json` export only when generated at/after the event's start. `feedback recompute-clv [--dry-run]` repairs already-settled rows carrying the bogus value. (3) Retention: `feedback retention --cutoff-days 90 [--dry-run]` clears only the 8 columns nothing reads for training/reporting (`pack_path`, `policy_fingerprint`, `portfolio_mode`, `pre_cap_units`, `portfolio_units`, `cap_reasons`, `projection_feature_hash`, `projection_quality_flags`) on settled/never-played/unflagged snapshot rows past the cutoff, then `VACUUM`s. **Do not widen this column set** without checking `_joined_rows()` first — it backs `fit_blend_weights()`, `fit_stake_calibration_from_db()`, and `generate_report()` alike, and an earlier draft of this PR that slimmed the "obvious" research columns (signal components, probabilities, segment fields) silently zeroed out `eligible_samples` for both fitters.
