- **PR #109 summary**: Implements the "Tier 1 — Restore truth" ledger upgrade plan. (1) Recovery: `feedback recover --corrupted <path> --output <path>` salvages a corrupted `feedback.sqlite3` into a fresh, schema-current database (sqlite3 CLI `.recover` when installed, a row-by-row direct-salvage fallback otherwise that stops cleanly at the first unreadable page). Note for whoever runs this against the real `calibration/feedback.sqlite3.corrupted`: copy its `-wal`/`-shm` companions alongside it under the same stem first, or not-yet-checkpointed rows in them are unrecoverable. (2) CLV fix: root-caused `clv_line == 0.0000` across historical rows — `_latest_local_close` in `results.py` was picking the *taken* snapshot as its own "close" whenever an outcome had only ever been captured once (no exclusion of the row's own snapshot_id), silently reporting a false, precise zero instead of "unknown". Fixed to require a genuinely distinct, later local capture, falling back to the current `*_line_movement_latest.json` export only when it was generated at/after the event's start. `feedback recompute-clv [--dry-run]` repairs already-settled rows carrying the bogus value (fingerprint: stored `closing_line`/`closing_price` exactly equal the matched snapshot's own `line`/`price`), clearing to unknown when no real close can be found. (3) Retention: `feedback retention --cutoff-days 90 [--dry-run]` clears the wide research columns (signal components, projection hashes, portfolio caps, blend metadata, ...) on settled/never-played/unflagged snapshot rows (never `PLAY`/`BET` and `board != 'A_FLAGGED'`) past the cutoff, keeping identity/result-relevant fields, then `VACUUM`s to reclaim disk. `docs/feedback-loop.md` documents all three commands and corrects the stale "closing line is always the last local pregame quote" claim.
